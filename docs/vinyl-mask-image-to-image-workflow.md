# 彩胶位图资产：图生图流程、提示词与交付契约

日期：2026-10-19，2026-10-20 改为"照片变体 + 代码提取"  
适用项目：Record Mockup  
用途：供素材制作 agent、Claude 和人工操作图生图工具时共同使用。

## 1. 目标与适用范围

将彩胶照片转成可重新着色的位图形态。图生图只负责生成**照片**（真实感由它负责），覆盖蒙版由代码从照片的颜色里提取（极性和浓淡由它负责），最终通过平面换色和 3D 渲染验收。

流程：

**参考照片 → 照片变体（图生图，4.1） → 照片检查 → 颜色提取（代码，4.2） → 质检板（相似度、换色、3D） → 人工验收 → 登记烘焙。**

| 步骤 | 工具 |
| --- | --- |
| 照片变体 | `codex exec` 的生图工具，参考图作输入（4.1） |
| 颜色提取 | `tools/vinyl-photo-extract.py` → `layer1.png`（`layer2.png`）+ `extract.json` |
| 质检、隔离库烘焙、质检板 | `tools/vinyl-gen-qc.py --master layer1.png`，输出在 `output/texture-gen/`（被 gitignore） |
| 3D | `node cli/record-mockup.mjs render <scene> --page output/texture-gen/index.html` |
| 正式入库 | `tools/bake-vinyl-masks.py`（第 6 节），人工验收之后 |

本文描述制作与交付要求。照片检查和最终验收需要人工判断；提取、烘焙、缩略图和 manifest 登记由脚本完成。现有能力以这些脚本、`vinyl-masks/manifest.json` 和 `index.html` 为准。

## 2. 当前运行时契约

当前渲染器读取 RGB 图像的数值作为覆盖率：

| 通道 | 含义 |
| --- | --- |
| R | accent1 的覆盖率 |
| G | accent2 的覆盖率 |
| B | accent3 的覆盖率 |
| alpha | 不承担形状；文件应不透明 |

每个通道中 0 表示无覆盖，255 表示完全覆盖，中间值表示部分覆盖。渲染器依次按 R → G → B 混合对应颜色，后面的层会覆盖前面的层；这些值不自动构成总和为 1 的颜色分区。

**单层灰度图不能简单复制进 RGB 三个通道。** 单层若分配给 accent1，应令 R=灰度、G=0、B=0，否则三个颜色层会同时生效。

当前纹理的盘面直径对应整个正方形边长，匹配 record face UV。中心孔、标签、唱片轮廓和光照由渲染器处理。

当前着色模式包括：

- `regions`：按区域选择颜色。
- `accent`：底色加纹路色，其他颜色按已登记关系派生。
- `tonal`：由底色派生明暗等变化。

新增素材需按现有 manifest 与派生规则登记，不能仅凭目录前缀或生成图自动猜定模式。

**默认配色决定派生结果，必须有意识地选定。** `accent` 模式下第 2、3 色层如何跟随纹路色，`tonal` 模式下各层的深浅，都是烘焙时从这款素材的默认配色（底色 + 每层一个颜色）算出来的。灰度蒙版本身不带颜色，入库时要按“希望用户换色后各层保持什么关系”来定这套配色，而不是随手填。

按形态推荐的配色模式：

| 形态 | 推荐模式 | 说明 |
| --- | --- | --- |
| Smoke、Marbled、Ripple 等同一颜色的深浅变化 | `tonal` | 单层就够，用户只选底色和反差 |
| Splatter、Blob、Starburst 等有明显主次色 | `accent` | 用户选底色 + 纹路色 |
| 多色布局（Pinwheel、环带分色等） | `accent` | 第 1 层为纹路色，其余层按默认配色推算 |
| 半边、三分、四分等几何分色 | `regions` | 由代码绘制，不需要位图 |

## 3. 制作前：先确定语义

每次制作先记录以下内容：

| 项目 | 必须明确的内容 |
| --- | --- |
| 来源 | 原始图片路径、参考用途、可追溯来源 |
| 操作 | 直接从参考提取（4.3），或先做照片变体再提取（4.1） |
| 目标层 | 具体哪种颜料或哪一组形态 |
| 角色 | 底色布局 / 叠加效果 / 表面纹理 |
| 风格 | splatter、starburst、smoke、blob、ripple、swirl、liquid 等描述 |
| 通道 | 单层还是多层，如何映射到 R/G/B |
| 保留要求 | 哪些结构必须保留，边界偏软还是偏硬 |
| 几何 | 参考是否倾斜、遮挡、偏心或带有留白 |

角色按实际用途判断：Blob、Pinwheel 和环带通常可作布局；泼溅通常可作效果；沟槽和反光属于表面纹理。角色不由文件名前缀强制决定。

严重透视或遮挡的照片应先校正、换参考，或明确作为风格灵感使用。生图补全区域属于推测，不能宣称是恢复出的真实纹理。

**参考素材按授权分级。** 彩胶纹路多是压片时随机形成的，受保护的主要是照片本身（构图、光线）和标签设计；去掉标签、光影和透视后的灰度覆盖图离原照片已经很远，但忠实描摹某一张照片的纹路仍可追溯回去。因此按参考的授权决定允许的操作：

| 参考来源 | 例子 | 允许的操作 | 来源登记（manifest `source.kind`） |
| --- | --- | --- | --- |
| 自有 | 自己拍摄的实物、自己生成的图 | 4.3 直接提取，或 4.1 照片变体 | `user` / `generated` |
| 开放授权 | Unsplash、Pexels、CC BY / CC BY-SA / CC0 | 4.3 直接提取，或 4.1 照片变体 | `licensed`，写明授权和作者链接，按授权署名 |
| 无授权 | Pinterest、别人的商品照、其他应用导出的素材（含 VinylLab 中来源为商品照的母版） | **只能做 4.1 照片变体**，再从生成的照片提取；不直接提取参考 | `unlicensed-reference`，保留原图链接或路径，`operation` 注明照片变体 |

无授权参考的额外要求：

- 参考只用来确定形态气质（密度、纹丝粗细、拉伸方向、边缘软硬），输出必须是新结构，不能只是原图纹路的旋转、镜像、缩放或局部修补。
- 入库前做相似度检查：`vinyl-gen-qc.py` 用同一个提取器处理参考照片，与候选在任意旋转、镜像下比较（归一化相关）。阈值 0.7：互不相关的彩胶两两在 0.27 左右、最高 0.54，旋转加模糊的描摹副本约 0.93。超过阈值的退回重做（见 5.1）。
- 厂牌刻意设计、可辨认的特效款（图案、文字、角色形状等）不作参考。
- Pinterest 只能手动挑图或给出 pin 链接，不批量抓取。

这是接受了低但非零风险的做法：无授权来源的条目都能凭登记查到，需要时可以整批替换。

## 4. 生成与提取

### 4.0 为什么不让模型直接画蒙版

2026-10-20 用同一张烟雾胶参考试过四版"让模型直接输出灰度覆盖蒙版"（原 4.1 / 4.3 的做法）：极性反过、覆盖铺满整盘、画成爆炸放射、只有锐利笔触没有薄雾、团块等距排成一圈、细纹像裂纹，每版都要靠黑场、伽马、增益补救。原因是图像模型见过大量彩胶照片，几乎没见过"彩胶蒙版"，蒙版对它是陌生任务，它会滑回自己的先验（墨水漩涡、分形、放射）。纯文生图和程序模拟也复刻不出压片的质感。

改为模型只生成照片后，同一张参考一次就得到了接近实物的结果。直接生成蒙版不再作为流程的一部分。

### 4.1 照片变体（主路径）

以参考照片为输入，让模型生成"同一批次压出来的另一张唱片"的产品照片。这个说法很关键：材料和工艺相同，所以纹路气质被参考约束住；每一处排布不同，所以是新结构。

```text
附图是一张彩胶唱片照片，作为风格参考：【材料描述】。

请生成一张新的产品照片：同一批次压出来的另一张唱片。材料和压片工艺完全相同，所以底胶颜色、颜料颜色、浓淡层次、纹路粗细、团块大小、疏密程度都和参考一致，纹路的走向也和参考一样——【走向】。但纹路的具体排布是全新的，每一处都在不同位置——不是参考的复制、旋转、镜像或局部修改。

不要：【这款不该出现的形态】。

拍摄要求（为了之后能从照片里干净地提取颜料分布）：
- 严格正俯拍，相机正对中心孔，无透视、无倾斜，唱片是正圆。
- 唱片居中，直径约占画面边长的 92%，四周留一点纯色背景。
- 背景是均匀的纯中灰色，无纹理、无阴影。
- 光线均匀柔和、完全漫射：没有高光、没有反光条、没有暗角、没有渐变，盘面各处亮度一致。
- 看不到沟槽纹路和划痕，盘面像哑光一样平整。
- 中心标签是一张完全空白的哑光纸，与底胶颜色相近的浅色，没有任何文字、图案或 logo。
- 没有手、封套、道具、文字或水印。
```

调用（提示词放在 `-i` 前面，`-i` 会吞掉后面的参数；stdin 要关掉，否则在后台会一直等输入）：

```bash
codex exec --skip-git-repo-check -s workspace-write -C <目录> "Read prompt.txt and use your image generation tool, with the attached image as the input reference, to produce exactly the photo prompt.txt describes. Copy the generated image, unmodified, into the current directory as gen.png." -i <目录>/ref.jpg < /dev/null
```

【材料描述】写清底胶、颜料和形态，例如：

| 形态 | 材料描述示例 |
| --- | --- |
| Smoke 烟雾 | 白色半透明底胶里混着黑色烟雾颜料：稀疏的深色烟芯、拖出的细纹、整盘一层淡灰薄雾 |
| Marble 大理石（环形） | 黑白大理石胶：白色、浅灰和黑色颜料互相交融，一圈圈绕着中心的环形流纹，环带宽窄不一、有断续和交叠 |
| Splatter 泼溅 | 奶白底胶上溅着黑色颜料：不规则的径向长条、短滴和孤立颗粒 |
| Blob / Color-in-color | 透明底胶中心有一团不规则的橙色色块，边界有窄幅自然过渡 |

【走向】和【这款不该出现的形态】必须按这一张参考来写，不能套用别的形态。例如烟雾写"沿半径方向被轻微拉开"、不要"墨水漩涡"；环形大理石写"以绕中心的环形、弧形流纹为主"、不要"从中心放射的花瓣、星芒、风车"；云团写"大块柔和云团，没有明显方向"。2026-10-20 曾把烟雾的"沿半径方向"写进通用模板，三张环形大理石都生成成了放射状花瓣。

参考本身就是正俯拍、光线较平的产品照效果最好；斜拍、手持、强反光的参考先换掉。

### 4.2 颜色提取

```bash
python3 tools/vinyl-photo-extract.py <目录> [--accents 2] [--crop 0.975]
```

1. 盘面：与背景色不同的像素，中心取质心，半径由面积反推。
2. 在盘缘以内裁一个正方形（默认保留 97.5% 半径），盘缘的反光和边线不进蒙版。标签区域运行时固定被标签盖住，不必补全。
3. 在 OKLab 里聚类：数量最多的一簇是底胶色，离它最远的一簇是纹路色。每个像素按它在"底胶 → 纹路色"连线上的位置算覆盖率（线性解混，符合半透明颜料的混合方式），最浓的 0.5% 定为 1。
4. `--accents 2`：两种纹路色不在同一条线上时（例如浅蓝底上同时有白纹和深蓝纹），对两种颜色同时做最小二乘解混，输出两层。两层出自同一张照片，天然对齐。
5. 输出 `layer1.png`（`layer2.png`）和 `extract.json`：盘面几何、找到的底胶色和纹路色（直接作默认配色）、底胶亮度的离散度（偏大说明光照漏进了蒙版）。

### 4.3 自有或开放授权参考：直接提取

授权允许时可以跳过 4.1，直接用 4.2 处理参考照片本身。前提是照片正俯拍、光线较平；照片里的光照、反光和沟槽会按颜色差混进蒙版，必要时仍先做 4.1 得到一张打光平整的照片。

### 4.4 多色布局

多层必须共享同一几何坐标：从同一张照片解混（4.2 的 `--accents 2`），或沿用 VinylLab 的聚类提取（输出 `field.png + layers.png + meta.json`，按 VinylLab 格式入库，第 6 节）。不要分别生成几张互补色区后假定它们自动对齐，也不要把多色图整体转灰度来代替分层。

## 5. 候选检查与后处理

### 5.1 检查生成候选

生成的照片：

- 是否正俯拍、正圆、居中？偏心会让泼溅、星芒看起来是歪的，也会让提取裁偏。
- 光线是否均匀，有没有高光条、暗角、渐变？这些会按颜色差进入蒙版（看 `extract.json` 的 `baseLightnessStd`）。
- 标签是否空白，盘面有没有文字、logo？
- 纹路是否和参考同一气质：烟雾有没有变成墨水漩涡，泼溅有没有变成规则星形，团块有没有等距排成一圈？
- 有没有生成瑕疵：像素拖影、重复图块、局部糊掉？

提取后的蒙版与质检板：

- 底胶区域是否干净，纹路色层是否只在颜料处？
- 无授权参考：相似度是否低于阈值（第 3 节）？
- 换色和 3D 下是否仍像真实压片（7.2、7.3）？

失败时先改材料描述或重生成照片。不要用强阈值或调色掩盖结构问题。

### 5.2 规范化为母版

- 保存未经修改的原始输出（`gen.png`）和参考（`ref.jpg`），记录尺寸与哈希；`vinyl-gen-qc.py` 写进 manifest 的 `source`。
- 中心、有效盘径和裁切由 4.2 自动求出并写进 `extract.json`，不要手工拉伸非正方形照片。
- 将 8 位输出存成 16 位只改变容器，不会获得新的有效细节。
- 不对素材统一拉满直方图或二值化，避免改变烟雾浓度与软边缘。提取后的覆盖率已经按颜色差标定，一般不需要再调；如确有需要（例如想让淡雾更明显），改提取参数并记录，而不是事后调色。

本项目不要求方形纹理相对边可无缝平铺。

### 5.3 field 与 layers 的区别

单层生成源图可以表示覆盖率，但现有 VinylLab 聚类母版的 `field.png` 通常是非底色颜料的综合标量场，不能自动等同于任一独立 accent 的 alpha。

如需交付兼容 VinylLab 的 `field.png + layers.png + meta.json`，应沿用其烘焙管线并注明模式。多通道转 field 前必须定义合成语义，不默认求和、平均或取最大值。Record Mockup 当前运行时主要使用打包的 RGB 覆盖图。

## 6. 运行时打包与资产登记

### 6.0 入库：烘焙脚本的输入

母版不进仓库，放在本地母版根目录下，每款一个以 ID 命名的文件夹。`tools/bake-vinyl-masks.py` 接受两种母版：

| 母版 | 文件夹内容 | 几何 | 默认配色来源 |
| --- | --- | --- | --- |
| 灰度分层（4.2 提取或其他来源） | 每个色层一张单通道 PNG（8 或 16 位），1–3 张，同一尺寸 | 正方形，唱片取内切圆（4.2 的输出已是盘面内的正方形） | 在登记项里写明 `base` 和 `colors`（4.2 的 `extract.json` 给出） |
| VinylLab 套件 | `field.png` + `layers.png`（RGB）+ `meta.json` | 盘面占 `meta.disc_frac` 宽度 | `meta.cluster_colors` |

在脚本的 `CURATED` 里为新素材加一项。灰度分层的写法：

```python
'smoke-g01': {
    'role': 'effect',                # layout 底色布局 / effect 叠加效果
    'palette': 'tonal',              # accent / tonal，见第 2 节
    'layers': ['layer1.png'],        # 依次对应 R、G、B，即 accent1..3
    'base': '#2a6f4e',               # 默认底色
    'colors': ['#8fc9a8'],           # 每层一个默认颜色，派生规则从这里算出
    'source': {'prompt': '…', 'model': '…', 'date': '2026-10-20'},  # 写进 manifest
    # 可选：'crop': 0.97 裁掉外圈；'floor': True 去底灰；'status': 'review'
},
```

然后运行：

```bash
python3 tools/bake-vinyl-masks.py --src <母版根目录> --preview <预览目录> smoke-g01
```

脚本会拒绝非正方形、带透明像素或各层尺寸不一致的输入，不会自动拉伸；颜色明显偏离灰度时会给警告并按亮度读取。输出是第 6.1 节要求的运行时文件，外加面板缩略图和 manifest 条目；预览目录里有两套配色的平面对照图，可直接用于 7.2 节的检查。

### 6.1 文件要求

- 生成 8 位 RGB PNG。
- R/G/B 对应 accent1/2/3 的软覆盖率，未使用通道全部为 0。
- 文件不透明；若存在 alpha，则全部为 255。
- 通道是数值数据，不进行美术调色、自动对比度增强或改变数值的色彩转换。
- 盘面直径占满正方形边长，匹配当前 UV；从带安全边距的母版导出时进行明确裁切。
- 层顺序固定并记录，重叠行为需与当前逐层合成一致。
- 不在覆盖蒙版中编码高光、浮雕、沟槽或液体厚度。

### 6.2 来源及参数记录

以下信息是新增资产需要保留的记录要求，不意味着当前 manifest 已有同名字段。具体存放位置由实现方对照现有 schema 决定，必要时使用独立的来源文件。

| 信息 | 内容 |
| --- | --- |
| 稳定 ID | 图案标识、版本、角色和风格 |
| 来源 | 参考图路径及可追溯来源、原始输出路径 |
| 生成记录 | 完整 prompt、可获得的模型名称、日期和工具参数；未提供的信息明确记为未知 |
| 语义 | 每个通道对应的形态、层顺序及覆盖含义 |
| 几何 | 源尺寸、中心、有效盘径、裁切和缩放规则 |
| 处理记录 | 灰度转换、底灰处理、位深和通道打包参数 |
| 配色 | 与现有 palette 规则相容的默认色与派生配置 |
| 验证 | 质量状态、已知瑕疵、预览与验收记录 |
| 校验 | 原始输出及运行时文件哈希 |

正式库使用项目内的相对路径，不依赖某台机器的 `/Users/...` 绝对路径。保留来源记录；本地存在某张图不代表其来源已经核实。

## 7. 验收流程

### 7.1 文件与通道

- [ ] 文件可解码，尺寸、位深、模式正确。
- [ ] alpha 全不透明，未使用通道为 0。
- [ ] 单独查看 R/G/B，形态与登记含义一致。
- [ ] 多层同坐标且合成顺序明确，无意外错位。
- [ ] manifest 文件路径有效，不静默替换成另一张素材。

### 7.2 换色

至少检查三组：浅底深纹、深底浅纹、高色差配色。

- [ ] 换色后形态仍成立，无非预期整体底灰。
- [ ] 改底色不会意外改变目标层的形状。
- [ ] 改目标色不会让其他独立色层同时变色；派生色模式按登记规则检查。
- [ ] 烟雾保留软过渡，色块及液滴保留边界。
- [ ] 高亮区域确实是颜料形态，而不是源图灯光残影。

不要为所有素材设置统一“必须达到纯白峰值”的门槛，稀薄烟雾未必存在完全覆盖区域。

### 7.3 3D 与 CLI

使用当前 CLI schema 写场景，通过 `node cli/record-mockup.mjs render <spec.json> -o <out.png> --json` 渲染并检查图片及 warnings。

- [ ] 正面近景、倾斜视角下形态清晰，无盘外条纹或盘缘接缝。
- [ ] 放射状形态的中心与唱片中心重合。
- [ ] 标签、中心孔和盘体几何正确，无旧标签残留。
- [ ] 透明与不透明材质下覆盖行为符合预期。
- [ ] 单唱片和双唱片配置正确。
- [ ] 光照、沟槽没有被烘焙重复叠加。

平面换色通过不代表 3D 验收通过；文件检查通过也不能替代看图。

## 8. 常见问题处理

| 问题 | 优先处理方式 |
| --- | --- |
| 整片被灰色覆盖 | 检查源图底灰及通道数值，确认是否本来就是连续烟雾；不要统一阈值清空 |
| 改一个颜色，多个层一起生效 | 检查是否把灰度直接复制到了 RGB 三个通道 |
| 盘缘出现条纹或圆环 | 检查有效盘径、裁切、安全区和照片盘缘残留 |
| 旋转后出现空白 | 当前实现不会发生：纹理绕中心旋转，唱片是正方形的内切圆，始终在画布内。只有改了采样方式或缩放规则时才需要检查 |
| 盘缘有一圈环 | 照片的盘缘反光或边线进了蒙版：减小 4.2 的 `--crop` |
| 多色交界错位 | 从同一张源图重新分层，或显式配准，不依赖分别生图 |
| 烟雾像脏污、底胶区域发灰 | 照片光照不均（看 `baseLightnessStd`）：重生成更平的照片，不要靠阈值清 |
| 液滴看起来只是平面色块 | 覆盖蒙版只提供形状，厚度、高光和边缘由材质实现 |
| 生成照片质感假（墨水漩涡、分形、爆炸放射） | 参考不够好（斜拍、强反光），或材料描述写成了抽象图案；换参考、把描述写成具体的胶和颜料 |
| 极性反了 | 4.2 按颜色聚类取底胶（数量最多的一簇），一般不会反；纹路占比过半时检查 `extract.json` 的 `clusters` |
