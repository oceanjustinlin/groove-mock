# 彩胶位图资产：图生图流程、提示词与交付契约

日期：2026-10-19  
适用项目：Groove Mock  
用途：供素材制作 agent、Claude 和人工操作图生图工具时共同使用。

## 1. 目标与适用范围

将彩胶照片、渲染参考或已有蒙版转成可重新着色的位图形态。图生图负责生成形态，代码负责几何归一化、通道打包及文件格式，最终通过平面换色和 3D 渲染验收。

流程：

**参考素材 → 指定目标层 → 图生图 → 候选检查 → 代码规范化 → 通道打包 → 登记 → 换色与 3D 验收。**

本文描述制作与交付要求。生成形态、候选检查和配色选择需要人工或 agent 判断；规范化、通道打包、缩略图和 manifest 登记由 `tools/bake-vinyl-masks.py` 完成，它的输入格式见第 6 节。现有能力以该脚本、`vinyl-masks/manifest.json` 和 `index.html` 为准。

## 2. 当前运行时契约

当前渲染器读取 RGB 图像的数值作为覆盖率：

| 通道 | 含义 |
| --- | --- |
| R | accent1 的覆盖率 |
| G | accent2 的覆盖率 |
| B | accent3 的覆盖率 |
| alpha | 不承担形状；文件应不透明 |

每个通道中 0 表示无覆盖，255 表示完全覆盖，中间值表示部分覆盖。渲染器依次按 R → G → B 混合对应颜色，后面的层会覆盖前面的层；这些值不自动构成总和为 1 的颜色分区。

**单层灰度图不能简单复制进 RGB 三个通道。** 单层若分配给 accent1，应令 R=灰度、G=0、B=0，否则三个颜色层会同时生效。

当前纹理的盘面直径对应整个正方形边长，匹配 record face UV。中心孔、标签、唱片轮廓和光照由渲染器处理。

当前着色模式包括：

- `regions`：按区域选择颜色。
- `accent`：底色加纹路色，其他颜色按已登记关系派生。
- `tonal`：由底色派生明暗等变化。

新增素材需按现有 manifest 与派生规则登记，不能仅凭目录前缀或生成图自动猜定模式。

**默认配色决定派生结果，必须有意识地选定。** `accent` 模式下第 2、3 色层如何跟随纹路色，`tonal` 模式下各层的深浅，都是烘焙时从这款素材的默认配色（底色 + 每层一个颜色）算出来的。灰度蒙版本身不带颜色，入库时要按“希望用户换色后各层保持什么关系”来定这套配色，而不是随手填。

按形态推荐的配色模式：

| 形态 | 推荐模式 | 说明 |
| --- | --- | --- |
| Smoke、Marbled、Ripple 等同一颜色的深浅变化 | `tonal` | 单层就够，用户只选底色和反差 |
| Splatter、Blob、Starburst 等有明显主次色 | `accent` | 用户选底色 + 纹路色 |
| 多色布局（Pinwheel、环带分色等） | `accent` | 第 1 层为纹路色，其余层按默认配色推算 |
| 半边、三分、四分等几何分色 | `regions` | 由代码绘制，不需要位图 |

## 3. 制作前：先确定语义

每次制作先记录以下内容：

| 项目 | 必须明确的内容 |
| --- | --- |
| 来源 | 原始图片路径、参考用途、可追溯来源 |
| 操作 | 从参考提取形态，或基于已有蒙版生成新变体 |
| 目标层 | 具体哪种颜料或哪一组形态 |
| 角色 | 底色布局 / 叠加效果 / 表面纹理 |
| 风格 | splatter、starburst、smoke、blob、ripple、swirl、liquid 等描述 |
| 通道 | 单层还是多层，如何映射到 R/G/B |
| 保留要求 | 哪些结构必须保留，边界偏软还是偏硬 |
| 几何 | 参考是否倾斜、遮挡、偏心或带有留白 |

角色按实际用途判断：Blob、Pinwheel 和环带通常可作布局；泼溅通常可作效果；沟槽和反光属于表面纹理。角色不由文件名前缀强制决定。

严重透视或遮挡的照片应先校正、换参考，或明确作为风格灵感使用。生图补全区域属于推测，不能宣称是恢复出的真实纹理。

**参考素材的红线：** 其他应用自带或导出的素材，以及别人商品照里的唱片，不能作为要入库发布的素材的图生图输入；图生图的结果仍是它们的衍生品。这类图只能用来理解形态，入库素材的参考应是自己拍摄、自己生成或已确认可用的图。

## 4. 图生图提示词

### 4.1 从彩胶参考提取一个覆盖层

将【目标形态】替换成明确对象，例如“蓝色径向泼溅”或“白色烟雾颜料”。

```text
将参考图片中的【目标形态】转译为可重新着色的二维灰度覆盖蒙版。

参考图片只用于确定颜料形态。保留主要分支的位置、方向、长短、
疏密、大小差异、断裂、孔隙和边缘气质。

输出一张正方形、正视、无透视的平面纹理。
纹理铺满整张正方形画布直到四条边，不要画成圆形或圆盘，
四角也要延续同样的形态。
放射状的形态以画面正中心为中心展开。
背景纯黑；目标颜料覆盖区域为白色；灰色只表示目标颜料的
部分覆盖或柔和过渡，不表示灯光、阴影或表面反射。

删除底色颜料、唱片标签、文字、中心孔、唱片外轮廓、
沟槽、划痕、反光、阴影、厚度和环境背景。

把被标签遮挡的中心区域补成自然连续的形态；
补全部分属于推测，不添加文字或标志。

只输出一张蒙版。不要输出唱片产品照、样机、对比图、
分栏图、边框、说明文字或水印。
使用不透明黑色背景，不使用透明背景。
```

提示词不能保证像素严格灰度、正确位深或精确尺寸，必须经过后处理与检查。

### 4.2 根据形态追加约束

一次选择与目标相符的一项，追加到通用提示词后。

| 类型 | 追加提示词 |
| --- | --- |
| Splatter 泼溅 | 保留不规则的径向长条、短滴和孤立颗粒；避免均匀放射、等间距线条及规则星形。效果以外保持纯黑。 |
| Starburst 星芒 | 保留从共同中心展开的连续分支、宽扇形和自然断裂；避免变成均匀太阳光束。 |
| Smoke 烟雾 | 使用连续、非均匀的密度变化，保留稀薄边缘和局部深核；允许大面积中灰，避免无结构的整体灰雾和单侧打光梯度。 |
| Blob 色块 | 保留不规则闭合轮廓及内部孔隙；内部覆盖趋近白色，外部纯黑，边界只有窄幅自然过渡。 |
| Ripple / Swirl 环带 | 保留宽度变化、偏心和局部断裂；不要生成细密沟槽，也不要把环带画成发光圆环。 |
| Liquid 液滴 | 保留圆润液池、液滴及内部反相小孔；相边界清楚，只有抗锯齿过渡，不生成高光、浮雕或投影。 |

### 4.3 基于已有蒙版生成新变体

```text
以输入灰度蒙版为形态参考，生成同一系列的新变体。

保持相近的覆盖比例、结构尺度、边缘软硬和视觉复杂度。
重新组织主要分支、颗粒位置与局部连接关系。
产生明显不同的新结构，不能只是旋转、镜像或缩放原图。

黑色表示无覆盖，白色表示完全覆盖，灰色表示部分覆盖。
保持原图的软硬边缘特征，不添加整体底灰。
不要添加唱片轮廓、中心孔、标签、沟槽、光照或文字。
纹理铺满整张正方形画布直到四条边，不要画成圆形；放射状形态以画面正中心为中心。
只输出一张不透明、正方形灰度纹理。
```

### 4.4 多色布局的生成策略

多层必须共享同一几何坐标。优先采用以下方式之一：

1. 从同一张生成图分割多个颜料区域；生成阶段让颜料使用易区分的平涂颜色，不加入光照，再由代码分层。分层可直接沿用 VinylLab 现有的聚类提取（输出 `field.png + layers.png + meta.json`），不需要另写一套；它的输出可以按 VinylLab 格式入库（第 6 节）。
2. 对同一张参考做受约束的分层编辑，保持画布、形状和坐标不动，只隔离目标层，并验证层间配准。

不要分别生成几张互补色区后假定它们自动对齐。不要把多色图整体转灰度来代替分层。模型输出的伪彩色图也不能直接视为已经正确打包的 RGB 覆盖数据。

## 5. 候选检查与后处理

### 5.1 检查生成候选

- 是否只保留了目标形态？
- 纹理是否铺满整个正方形？画成圆盘、外面留黑的候选会在盘缘留下一圈环，应重生成。
- 放射状形态的中心是否在画面正中？偏心会让泼溅、星芒看起来是歪的。
- 是否仍有标签、文字、中心孔、盘缘、沟槽、光影或方形边框？
- 是否把自然结构改成了规则星形、均匀线条或对称图案？
- 烟雾是否保留连续灰度，液滴是否保留清楚相边界？
- 中心补全是否突兀，主要结构是否因去除标签而断裂？

失败时先改提示词或重生成。不要用强阈值掩盖结构问题。

### 5.2 规范化为母版

- 建议母版为 2048×2048；记录模型实际输出尺寸及任何缩放操作。
- 保存未经修改的原始输出。
- 将候选转换为真正单通道灰度，检查色偏和 alpha。
- 记录中心、有效盘径、偏移和裁切规则。
- 去掉照片留白、物理盘缘和不需要的背景；不要无条件强行拉伸非正方形照片。
- 需要母版边缘延拓时由代码生成，并记录有效盘径；不能让延拓条纹进入可见盘面。
- 将 8 位输出存成 16 位只改变容器，不会获得新的有效细节。
- 不对所有素材统一拉满直方图或二值化，避免改变烟雾浓度与软边缘。

形态应以完整平面场交付；圆形裁切和中心孔由几何处理。本项目不要求方形纹理相对边可无缝平铺。

### 5.3 field 与 layers 的区别

单层生成源图可以表示覆盖率，但现有 VinylLab 聚类母版的 `field.png` 通常是非底色颜料的综合标量场，不能自动等同于任一独立 accent 的 alpha。

如需交付兼容 VinylLab 的 `field.png + layers.png + meta.json`，应沿用其烘焙管线并注明模式。多通道转 field 前必须定义合成语义，不默认求和、平均或取最大值。Groove Mock 当前运行时主要使用打包的 RGB 覆盖图。

## 6. 运行时打包与资产登记

### 6.0 入库：烘焙脚本的输入

母版不进仓库，放在本地母版根目录下，每款一个以 ID 命名的文件夹。`tools/bake-vinyl-masks.py` 接受两种母版：

| 母版 | 文件夹内容 | 几何 | 默认配色来源 |
| --- | --- | --- | --- |
| 灰度分层（图生图产出） | 每个色层一张单通道 PNG（8 或 16 位），1–3 张，同一尺寸 | 正方形，纹理铺满画布，唱片取内切圆 | 在登记项里写明 `base` 和 `colors` |
| VinylLab 套件 | `field.png` + `layers.png`（RGB）+ `meta.json` | 盘面占 `meta.disc_frac` 宽度 | `meta.cluster_colors` |

在脚本的 `CURATED` 里为新素材加一项。灰度分层的写法：

```python
'smoke-g01': {
    'role': 'effect',                # layout 底色布局 / effect 叠加效果
    'palette': 'tonal',              # accent / tonal，见第 2 节
    'layers': ['layer1.png'],        # 依次对应 R、G、B，即 accent1..3
    'base': '#2a6f4e',               # 默认底色
    'colors': ['#8fc9a8'],           # 每层一个默认颜色，派生规则从这里算出
    'source': {'prompt': '…', 'model': '…', 'date': '2026-10-20'},  # 写进 manifest
    # 可选：'crop': 0.97 裁掉外圈；'floor': True 去底灰；'status': 'review'
},
```

然后运行：

```bash
python3 tools/bake-vinyl-masks.py --src <母版根目录> --preview <预览目录> smoke-g01
```

脚本会拒绝非正方形、带透明像素或各层尺寸不一致的输入，不会自动拉伸；颜色明显偏离灰度时会给警告并按亮度读取。输出是第 6.1 节要求的运行时文件，外加面板缩略图和 manifest 条目；预览目录里有两套配色的平面对照图，可直接用于 7.2 节的检查。

### 6.1 文件要求

- 生成 8 位 RGB PNG。
- R/G/B 对应 accent1/2/3 的软覆盖率，未使用通道全部为 0。
- 文件不透明；若存在 alpha，则全部为 255。
- 通道是数值数据，不进行美术调色、自动对比度增强或改变数值的色彩转换。
- 盘面直径占满正方形边长，匹配当前 UV；从带安全边距的母版导出时进行明确裁切。
- 层顺序固定并记录，重叠行为需与当前逐层合成一致。
- 不在覆盖蒙版中编码高光、浮雕、沟槽或液体厚度。

### 6.2 来源及参数记录

以下信息是新增资产需要保留的记录要求，不意味着当前 manifest 已有同名字段。具体存放位置由实现方对照现有 schema 决定，必要时使用独立的来源文件。

| 信息 | 内容 |
| --- | --- |
| 稳定 ID | 图案标识、版本、角色和风格 |
| 来源 | 参考图路径及可追溯来源、原始输出路径 |
| 生成记录 | 完整 prompt、可获得的模型名称、日期和工具参数；未提供的信息明确记为未知 |
| 语义 | 每个通道对应的形态、层顺序及覆盖含义 |
| 几何 | 源尺寸、中心、有效盘径、裁切和缩放规则 |
| 处理记录 | 灰度转换、底灰处理、位深和通道打包参数 |
| 配色 | 与现有 palette 规则相容的默认色与派生配置 |
| 验证 | 质量状态、已知瑕疵、预览与验收记录 |
| 校验 | 原始输出及运行时文件哈希 |

正式库使用项目内的相对路径，不依赖某台机器的 `/Users/...` 绝对路径。保留来源记录；本地存在某张图不代表其来源已经核实。

## 7. 验收流程

### 7.1 文件与通道

- [ ] 文件可解码，尺寸、位深、模式正确。
- [ ] alpha 全不透明，未使用通道为 0。
- [ ] 单独查看 R/G/B，形态与登记含义一致。
- [ ] 多层同坐标且合成顺序明确，无意外错位。
- [ ] manifest 文件路径有效，不静默替换成另一张素材。

### 7.2 换色

至少检查三组：浅底深纹、深底浅纹、高色差配色。

- [ ] 换色后形态仍成立，无非预期整体底灰。
- [ ] 改底色不会意外改变目标层的形状。
- [ ] 改目标色不会让其他独立色层同时变色；派生色模式按登记规则检查。
- [ ] 烟雾保留软过渡，色块及液滴保留边界。
- [ ] 高亮区域确实是颜料形态，而不是源图灯光残影。

不要为所有素材设置统一“必须达到纯白峰值”的门槛，稀薄烟雾未必存在完全覆盖区域。

### 7.3 3D 与 CLI

使用当前 CLI schema 写场景，通过 `node cli/groove-mock.mjs render <spec.json> -o <out.png> --json` 渲染并检查图片及 warnings。

- [ ] 正面近景、倾斜视角下形态清晰，无盘外条纹或盘缘接缝。
- [ ] 放射状形态的中心与唱片中心重合。
- [ ] 标签、中心孔和盘体几何正确，无旧标签残留。
- [ ] 透明与不透明材质下覆盖行为符合预期。
- [ ] 单唱片和双唱片配置正确。
- [ ] 光照、沟槽没有被烘焙重复叠加。

平面换色通过不代表 3D 验收通过；文件检查通过也不能替代看图。

## 8. 常见问题处理

| 问题 | 优先处理方式 |
| --- | --- |
| 整片被灰色覆盖 | 检查源图底灰及通道数值，确认是否本来就是连续烟雾；不要统一阈值清空 |
| 改一个颜色，多个层一起生效 | 检查是否把灰度直接复制到了 RGB 三个通道 |
| 盘缘出现条纹或圆环 | 检查有效盘径、裁切、安全区和照片盘缘残留 |
| 旋转后出现空白 | 当前实现不会发生：纹理绕中心旋转，唱片是正方形的内切圆，始终在画布内。只有改了采样方式或缩放规则时才需要检查 |
| 盘缘有一圈环或纹理在圆边截断 | 生成图被画成了圆盘：按 4.1 节要求重生成铺满正方形的版本，或用 `crop` 裁掉外圈 |
| 多色交界错位 | 从同一张源图重新分层，或显式配准，不依赖分别生图 |
| 烟雾像脏污 | 检查大尺度打光、沟槽、反射是否被当成颜料密度 |
| 液滴看起来只是平面色块 | 覆盖蒙版只提供形状，厚度、高光和边缘由材质实现 |
| 生成图是彩胶产品照 | 强调二维数值蒙版，并移除产品摄影、真实材质和打光描述 |
